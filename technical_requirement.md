# Техническое задание
## Веб-сервис мониторинга ментального состояния «Название»

---

## 1. Введение

Техническое задание написано для разработчиков сервиса мониторинга ментального состояния

### Контекст проекта

Существует множество сервисов для поддержки ментального состояния, работа которых затрагивает разные сферы этого процесса: отслеживание эмоций, упражнения для снижения тревоги, психологические тесты для самопознания и др. Есть приложения, которые объединяют две или три функции, но чаще всего пользователю, который следит за психологическим состоянием, необходимо несколько приложений сразу.

Мы решили создать веб-сервис, которое объединяет в себе:
- психологические тесты для саморазвития;
- создание дневников эмоций;
- медитации;
- мини-игры, которые помогут отвлечься от тревожных мыслей.

### Термины и сокращения

| Термин | Определение |
|--------|-------------|
| **Пользователь** | Зарегистрированный на сайте человек |
| **Заметка** | Краткая записка от пользователя о своём настроении в календаре |
| **Психологический тест** | Небольшой опрос об индивидуально-психологических особенностях пользователя (черты характера, темперамент, тип личности) |
| **Дневник эмоций** | Разновидность ежедневника, где пользователь каждый день отмечает уровень своего настроения |
| **Статистика** | Дашборд с анализом дневника эмоций для отображения изменения уровня настроения в течение выбранного периода времени |
| **Медитация** | Психологическое упражнение, направленное на снижение уровня стресса и развитие самоосознанности, представленное в формате аудиодорожки с голосом ведущего |
| **Мини-игра** | Небольшая игра (до 15 минут), направленная на расслабление пользователя и снижение уровня стресса |
| **Шкала стресса** | Короткий опрос, позволяющий оценить изменение ментального состояния человека до и после используемой функции (если после использования состояние улучшается — функция эффективна) |

## 2. Назначение и цели создания веб-сервис

### Проблема
Отсутствие системы, которая позволяет полноценно и всесторонне контролировать ментальное состояние.

### Целевая аудитория
Подростки от 14–18 лет и молодёжь в возрасте 18–30 лет, основным родом деятельности которых являются учёба и/или работа.

### Цель продукта
По итогам недели работы с веб-сервисом зафиксировать улучшение эмоционального состояния у **n%** пользователей на **≥ 1 пунктов** шкалы стресса путём сравнения результатов ежедневного трекинга.

### Задачи продукта

1. Разработать структуру БД для хранения записей ежедневного трекинга настроения, включая таблицы пользователей, ежедневных записей и тегов эмоций.
2. Реализовать механизм аутентификации и авторизации с поддержкой безопасного входа.
3. Разработать виджет ежедневного трекинга настроения.
4. Создать индикатор прогресса на главном экране, отображающий текущую оценку за сегодня и динамику относительно вчерашнего дня с визуализацией тренда.
5. Провести UI-тестирование адаптивности всех компонентов на мобильных устройствах и различных разрешениях экрана.
6. Внедрить систему персонализированных подсказок и рекомендаций на основе истории трекинга.
7. Добавить элементы геймификации.
8. Организовать бета-тестирование с фокус-группой из 50–100 представителей целевой аудитории для сбора обратной связи.
9. Подготовить документацию для пользователей и команды поддержки.

## 3. Характеристика объектов автоматизации

### Текущий процесс
Пользователь фиксирует заметки в телефоне или физическом дневнике и использует несколько приложений с трекерами одновременно.

### Недостатки процесса
- Дублирование функционала
- Необходимость скачивать несколько приложений / использовать несколько веб-сервисов
- Отсутствие общего видения ситуации

### Ограничения
- Веб-сервис не подразумевает постановку диагноза
- Веб-сервис не предназначен для оказания профессиональной медицинской помощи
- Не предполагает оказание медицинской помощи

### Допущения
- Пользователи в состоянии обратиться за квалифицированной помощью
- Пользователи не злоупотребляют функциями веб-сервиса

## 4. Требования к приложению

### 4.1. Функциональные требования

| Код | Требование |
|-----|------------|
| **[FR-001]** | Система должна требовать от пользователя авторизации для доступа к функционалу |
| **[FR-002]** | Система должна позволять пользователю создавать заметки |
| **[FR-003]** | Система должна хранить данные о прошлых заметках, дневниках эмоций и психологических тестах пользователя |
| **[FR-004]** | Система должна позволять пользователю редактировать прошлые заметки |
| **[FR-005]** | Система должна позволять пользователю ставить тест на паузу и возвращаться к нему позднее |
| **[FR-006]** | Система должна поддерживать интеграцию мини-игр |
| **[FR-007]** | Система должна показывать пользователю статистику по заполняемым им данным |
| **[FR-008]** | Система должна хранить медитации |
| **[FR-009]** | Система должна воспроизводить медитации с возможностью поставить их на паузу или перемотать |
| **[FR-010]** | Система должна отправлять пользователю напоминание на почту о необходимости заполнить дневник эмоций |
| **[FR-011]** | Система должна отображать пользователю интерактивную шкалу стресса для ввода оценки своего состояния до и после выполнения любой активности |

### 4.2. Роли пользователей и функции

| Роль | Функции |
|------|---------|
| **Гость** (неавторизованный пользователь) | Просмотр функционала веб-приложения |

| **Администратор** | Управление пользователями, модерация процессов |

## 5. Требования к информационному обеспечению

### Сущности

| Сущность | Описание сущности |
|----------|-------------------|
| **Пользователи (Users)** | Хранит данные о пользователях и их личную информацию |
| **Эмоции (Emotions)** | Хранит данные, заполняемые в дневнике эмоций, включая: эмоцию дня, степень, её силу и дату заполнения |
| **Заметки (Notes)** | Хранят текст заполненного «дневника» и дату написания |
| **Статистика (Statistics)** | Хранит данные об обращениях пользователя к статистике своих эмоций |
| **Медитации (Meditations)** | Хранит информацию о медитациях + ссылки на аудиодорожки для воспроизведения |
| **Прослушивание медитаций (Meditation_listening)** | Промежуточная таблица с информацией о прослушиваниях со стороны пользователя (связь «многие ко многим» между пользователями и медитациями) |
| **Игры (Games)** | Хранит данные об играх и ссылки на них |
| **Игровые сессии (Game_session)** | Промежуточная таблица с информацией об играх со стороны пользователя (связь «многие ко многим» между пользователями и играми) |
| **Активности (Activities)** | Соотносят активности (медитация / дневник эмоций и т.д.) и их названия для таблицы со шкалой стресса |
| **Уровень стресса (Stress_level)** | Фиксирует результаты опросов пользователя, используемые для оценки стресса |

![Диаграмма](https://drive.google.com/uc?export=view&id=19eCg3tKpEJu0tAf9F2zNK8ArynxlPon5)

### Типы связей

- Один пользователь может испытывать несколько эмоций (1:N)
- Один пользователь может прослушивать несколько медитаций (1:N)
- Один пользователь может испытывать разные уровни стресса (1:N)
- Один пользователь имеет доступ к нескольким статистикам (к статистике по нескольким активностям) (1:N)
- Один пользователь может создавать несколько заметок (1:N)
- Одной активности соответствуют разные уровни стресса (1:N)
- Многие пользователи могут играть в несколько игр через связующую таблицу game_sessions (N:N)
- Многие пользователи могут прослушивать несколько медитаций через связующую таблицу meditation_listening (N:N)
